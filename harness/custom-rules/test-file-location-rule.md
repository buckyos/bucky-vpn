# 独立测试文件目录规则

## 目标
- 统一独立测试文件的目录边界，避免测试专用文件混入生产源码树
- 让测试代码的位置在不同语言、模块和 Harness 阶段中保持一致且可审查

## 适用范围
- 仓库根目录或任一模块中存在 `src` 目录的代码
- implementation、testing、acceptance 阶段中新建、移动或修改的独立测试文件
- 名称或用途表明文件主要用于测试的单独文件，例如 `_test.rs`、`_tests.rs`、`test_*.py`、`*.test.*`、`*.spec.*`，以及由测试入口单独加载的测试专用模块

## 定义
- “独立测试文件”是指以单独文件存在、主要承载测试代码或测试辅助代码、且不属于生产构建所需实现的文件
- 直接写在生产源码文件中的内联测试块不是独立测试文件，例如 Rust 源文件内的 `#[cfg(test)] mod tests`；本规则不要求把这类内联测试拆出源码文件

## 强制规则
- 独立测试文件禁止放在 `src` 目录及其任意子目录中
- 独立测试文件必须放在与对应 `src` 目录同级的 `tests` 目录及其子目录中
- 根级 `src/...` 对应根级 `tests/...`；模块级 `<module>/src/...` 对应 `<module>/tests/...`
- 如果当前任务触及了已有的违规独立测试文件，必须在任务完成前将该文件迁移到对应的同级 `tests` 目录，并同步修正模块引用、测试入口或可见性边界
- 不得以访问私有实现、沿用历史布局或测试入口便利为由，把独立测试文件保留在 `src` 中；应调整测试接口、模块导出或测试组织方式

## 阶段处理
- Implementation：不得新建或遗留当前任务触及的 `src/**` 独立测试文件
- Testing：新增或迁移的独立测试文件及测试辅助文件必须进入对应的 `tests/**` 路径
- Acceptance：如果交付范围内仍存在当前任务新建、修改或移动的 `src/**` 独立测试文件，应判定为阻塞问题，不得通过验收

## 与其他规则的关系
- `vpn-web-no-new-tests-rule.md` 决定 `vpn_web` 是否允许新增测试；本规则仅在独立测试文件存在或被触及时约束其位置
- 未被当前任务触及的历史违规文件不要求在本任务中批量迁移，但后续任务一旦触及就必须按本规则处理

## 允许边界
- 生产源码文件中的内联测试块可以保留在 `src` 中
- 只有当前用户明确指示，或未来更高优先级且可审计的版本化仓库规则明确替代本规则时，才允许例外

## Review 指引
- 检查新增、移动和修改的测试专用文件是否位于任意 `src` 路径下
- 对每个独立测试文件确认其所在 `tests` 与对应 `src` 具有相同父目录
- 对任务触及的历史违规文件确认已完成迁移，并且测试入口、引用和可见性调整后仍可验证
- 不要把生产源码中的内联测试块误报为独立测试文件
